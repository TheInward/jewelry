# 第二轮漏洞与逻辑修复（2026-11-03）

目标：https://seleneith.com/ 。本轮检查自定义 AJAX、注册、收藏与搜索逻辑，并部署主题修复。

## 修复内容

1. **加购校验旁路及输入强制转换。** 自定义接口原先直接执行 `WC_Cart::add_to_cart(absint(...))`，负数会被转换为正商品 ID，且未执行表单层的 `woocommerce_add_to_cart_validation` 扩展校验。现在严格校验正整数 ID、商品类型、可售/库存/公开状态，传递父商品 ID、规格 ID 与属性进行扩展校验，再执行原生加购。原生库存校验仍由 WooCommerce 完成。[官方加购实现](https://woocommerce.github.io/code-reference/files/woocommerce-includes-class-wc-ajax.html)。
2. **混合操作导致失败前已修改购物车。** 旧接口可在同一请求依次执行加购、删除、改数量；后一个操作报错时，前一个可能已生效。现在每个请求只允许一种操作，数量与购物车 key 必须成对提供，在任何修改前拒绝歧义请求。
3. **接口输入边界和错误处理。** 拒绝数组代替字符串、异常商品 ID、超长字段及超过 100 个商品的列表；收藏合并在数据库查询前限制输入规模。失效删除 key 明确报错，服务端内部异常不直接发送给访客；本次接口失败产生的 WooCommerce 提示不再残留到后续结账页。
4. **多语言搜索断层。** 实际复现：法语 `collier` 弹窗返回 12 件商品；“查看全部”却被 `is_shop()` 分支当成全部商品目录，忽略搜索结果，同时 WordPress 默认搜索不匹配翻译标题。现在优先使用搜索结果模板，两处共用当前语言标题匹配，完整页保留分页和搜索词；搜索只为匹配页面构建商品价格与规格数据。搜索遵守 WooCommerce 的搜索可见性和缺货隐藏配置，并排除密码保护商品。
5. **收藏并发及失败状态。** 同一页面的收藏修改按顺序提交，成功保存后才更新本地状态；失败后再次点击仍执行正确操作。同商品多个按钮保持一致。“移至收藏”只有在收藏保存成功后才移除购物车项，访客本地存储失败也不会静默丢失购物车商品。
6. **延迟响应重新打开弹层。** 关闭购物袋或切换其他弹层后，过期请求只更新购物车计数，不再重新打开或覆盖当前弹层。
7. **注册字段和入口。** 服务端补齐密码缺失、数组字段、纯空格姓名和非正常隐私同意值的校验；关闭注册时不再显示不能使用的注册切换入口，前端切换也检查目标面板存在。
8. **订阅优惠码。** 邮箱改为校验完整输入，防止清洗时把格式错误地址静默改为另一地址；已用完次数的优惠码不再作为可用的新客优惠返回。本轮没有发送订阅邮件或创建优惠券。
